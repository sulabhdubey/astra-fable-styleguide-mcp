# v0.6.0 release notes

## Set up and check a supported project

- `stylecon init` guides file selection, button/dialog targets, visible title and
  optional native-field journeys. It writes a new configuration without running
  project scripts or overwriting existing configuration.
- `stylecon constitution pin` exports a validated snapshot from a team's
  canonical `/spec`. Projects bind it by full SHA-256; tokens generate custom CSS,
  and changes invalidate stale evidence. Exports cannot overwrite the canonical
  source tree.
- HTML reports show readable observations, rule guidance, limitations and evidence
  identifiers. Recheck comparisons require matching rules, configuration and
  coverage. Reports remain local and have no remote assets or telemetry.

## Installable CLI and delivery evidence

The release attaches `styleconstitution-cli-0.6.0.tgz`, `SHA256SUMS`, package
evidence and an exact-archive verification receipt. The release gate installs the
produced archive into a clean consumer and exercises setup, pinning, browser
reporting, guarded repair, recheck, stale refusal and undo before publication.
The CLI is not published to npm. See the [installation guide](PROJECT_ADOPTION.md).

CI includes distinct constitution fixtures, safe export boundaries, malformed or
changed pins, escaped HTML, incompatible comparisons, unsupported targets and
runtime failures. A manual consumer CI example supports JSON, SARIF or HTML output
and preserves failure/incomplete exit codes. No external AI service is required.

## Collaboration experiment

A bounded harness compares one role using self-review with independent Astra and
Fable proposals using the same installed model. Each arm has explicit call,
output, input and time limits. The initial local rehearsal produced zero valid
candidates in both arms; it establishes no collaboration advantage. See the
[method and limitations](COLLABORATION_COMPARISON.md).

## Compatibility and limits

Design tokens, component behavior and accessibility rules are unchanged from
v0.5.1; the canonical manifest advances to v0.6.0. Existing project configurations
continue to use bundled rules unless they explicitly pin a constitution. Report
identity metadata is additive; older reports without compatible configuration
bindings cannot be compared as new rechecks.

The verifier remains experimental and supports documented static light-DOM
journeys. Arbitrary frameworks, custom comboboxes, shadow DOM and complete
accessibility coverage remain outside scope. A passing report or exported
constitution does not authorize a repair or a release. The public MCP remains
read-only with eight tools. New release evidence and checksums accompany this
version; historical releases and snapshots are retained.
