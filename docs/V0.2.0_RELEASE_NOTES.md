# v0.2.0 release notes

## Design rules

- Inputs with automatically detected errors now require visible, field-specific correction text. The error is associated with its control using `aria-invalid` and `aria-describedby`, while existing supporting-text references and visible focus remain intact.
- The input component maps error text and invalid borders to semantic danger tokens. Deterministic contrast checks require at least 4.5:1 for danger text and 3:1 for the invalid border against the primary surface.
- The form pattern asks for the corrective message beside each affected control.

## Agent and developer integration

- The eight public MCP tool names remain stable. The public service stays read-only; proposal and release tools require separate configuration and authorization.
- The TypeScript client supports modern discovery and legacy initialization. Compliance reports include source locations and explicit coverage limits for the deterministic checks that ran.
- Immutable v0.1.0 and v0.2.0 `/spec` snapshots enable a real machine-readable version comparison. The comparison includes design-rule changes and manifest metadata.

## Compatibility and migration

Existing public tool names and arguments remain available. Compliance result fields are additive. An implementation that shows an invalid input only through border color or generic error text should add a visible correction message tied to the affected field and preserve existing `aria-describedby` references. Consumers that enforce the new design rules may need to update their invalid-input presentation.

## Governance scope

The design candidate was independently proposed and cross-reviewed by the two logical roles, passed deterministic evaluation, and received exact-hash design assent. Runtime proposals, candidates, and approvals remain process-local. Optional JSONL audit records are flushed locally, but they do not restore workflow state or establish multi-user identity. Role credentials identify configured credentials, not a person or model. A human approval of the exact final release commit is required before tagging or changing production.
