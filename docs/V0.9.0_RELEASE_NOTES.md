# v0.9.0 release notes

v0.9.0 brings token verification and reviewed individual/team workflows to the
installed CLI. Use the installer, archive and checksums from this release. Its
attached evidence identifies the exact tested source and connected release gate.

## Changes

- Import the supported, explicitly versioned Dembrandt export. Compare declared
  tokens against a controlled rendered page at the matching viewport. Preserve
  match, mismatch, unverified and incomplete results, including extraction gaps.
- Prepare selected-finding briefs for an existing coding agent, with current
  source, constitution and configuration identities and explicit coverage limits.
- Keep private Studio history across restarts and compare runs with matching
  scopes. Historical observations cannot restore live repair permission.
- Review and adopt an exact constitution pin, with stale-input refusal and
  recovery from interrupted writes. `/spec` remains the canonical rule source.
- Export reviewed offline HTML/JSON packets for clients and teammates. Retain
  every recorded outcome while omitting source paths and free-form diagnostics.
- Add individual/team workflow guidance and upstream dependency fixes.

## Compatibility and limits

Canonical design token values are unchanged. Existing supported configurations
remain usable. The new workflows are absent from the older v0.8.0 archive.

Checks cover configured targets and viewports, not whole applications. Extraction
degradation and unsupported values remain explicit. Review packet checksums show
internal integrity, not authenticated provenance or proof that an observation is
true. Numbered targets require sender context; omitted diagnostics can require
private follow-up. Packets open offline without JavaScript.

This release does not add hosted tenancy, SSO, signed attestations, arbitrary URL
scanning or full accessibility certification. Recorded collaboration comparisons
have not established an overall advantage. No external model calls are required
for CI. The documented cache dependency advisory exception remains in SECURITY.md;
passing the configured audit is not a zero-vulnerability claim.
