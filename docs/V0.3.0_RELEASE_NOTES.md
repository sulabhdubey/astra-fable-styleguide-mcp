# v0.3.0 release notes

## Design rules

- Buttons declare a minimum 40px target in both dimensions. This is a Style Constitution product rule, not a claim that WCAG requires 40px.
- The button's mapped focus-ring color must reach at least 3:1 contrast against the canonical primary surface. Rendered use on other adjacent surfaces still needs browser review.
- Dialog guidance now requires a programmatic name from the visible title, initial focus inside, focus containment while open, focus return to the trigger, and Escape dismissal when allowed. Implementations with an intentional non-dismissible exception must state it explicitly.

## Validation and integration

- `stylecon validate [--root <directory>]` validates a local StyleSpec from a standalone packed CLI. It reports rule codes and paths, with exit 0 for a valid spec, 1 for deterministic rule violations, and 2 for command or input errors. The CLI is included in the repository and is not published to a package registry.
- Token-file merging rejects prototype-related object keys before mutation. The CLI reports these as input errors.
- The existing eight public MCP tool names and arguments remain stable. The public service remains read-only by default; external AI is not required for CI.

## Compatibility and limits

Existing v0.1.0 and v0.2.0 snapshots remain immutable. Consumers enforcing the new StyleSpec rules may need to enlarge button targets, adjust focus-ring colors, and add dialog focus management. The canonical evaluator validates declared rules and tokens. It does not prove that arbitrary rendered interfaces satisfy the dialog interactions or all accessibility requirements; browser interaction checks are still required.
