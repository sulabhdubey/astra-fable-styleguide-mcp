# v0.3 coding-agent trial evidence

This is exploratory evidence from the v0.3 StyleSpec candidate. It is not release validation or an accessibility certification. The example was generated in a separate empty workspace from copies of `spec/components/button.json`, `spec/components/dialog.json`, `spec/accessibility/rules.json`, and `generated/css/tokens.css`; the agent was told not to edit the spec, use the network, or add dependencies.

## Codex CLI, Luna

On 2026-09-20, Codex CLI `0.155.0-alpha.9.2` with `gpt-5.6-luna` created a self-contained [button and dialog example](../tests/fixtures/agent-trial-codex-luna.html). The preserved file's SHA-256 is `f892da32f49c08de9e7428169c7eb41f5fb17acd87e1a2b8fa021c08077f6b8e`. The agent read the four supplied files, used the declared semantic color and sizing variables, and implemented a visible title, initial dialog focus, keyboard focus wrapping, Escape dismissal, and focus return. No source files in `/spec` changed during the trial.

Independent Edge browser observations on that file:

| Rule | Observation |
| --- | --- |
| Button target | The trigger rendered 40px high and wider than 40px. The CSS minimum applies to the dialog buttons, but their hidden state was not measured. |
| Dialog name | The accessibility tree named the dialog “Review your changes” from its visible heading. |
| Initial focus | Opening moved focus to Cancel. |
| Focus containment | Tab moved Cancel → Continue → Cancel; Shift+Tab moved Cancel → Continue. |
| Escape and return | Escape hid the dialog and returned focus to Open dialog. |

The generated example includes a `:focus-visible` outline using the mapped semantic focus color. Rendered contrast across every surface and assistive-technology behavior were not fully audited. The focus trap was exercised through keyboard navigation in this one example; it does not establish that other generated implementations contain focus. The static StyleSpec evaluator validates declared component rules and mapped tokens, not arbitrary browser behavior.

**Setup friction:** the agent needed an isolated workspace containing the four local inputs. The example does not call the public MCP service, so this trial tests use of local v0.3 rules rather than MCP discovery.

## Grok Build CLI, grok-4.6

On 2026-09-20, Grok Build CLI `0.2.3` with its default `grok-4.6` model generated a separate [button and dialog example](../tests/fixtures/agent-trial-grok-46.html) from the same four inputs in a fresh disposable Git repository. The preserved file's SHA-256 is `864727cdb56e5c034c3749c5e4a0293eff27c211b0086283089b716bf5a45b0a`. The run used low effort, no web search, no subagents, and no external dependencies. The four supplied inputs remained unchanged.

Source inspection found a declared 40px minimum for both button dimensions, a `:focus-visible` outline, a dialog named by its visible heading, initial focus inside the dialog, Tab wrapping, Escape dismissal, and focus return. These are implementation observations, not rendered or assistive-technology results. The generated handler also closes on overlay click, a behavior the supplied rules do not specify; `lastTrigger` is assigned through a redundant conditional. The agent identified unmeasured contrast and unspecified overlay behavior in its response. This artifact was not browser tested.

**Setup friction:** the first bounded CLI attempt stopped at an eight-turn limit before writing an artifact. The retry required a Git repository for codebase discovery and wrote the file, but a diagnostics upload received a 502 response after generation. This trial also uses local v0.3 rules, not the public v0.2 MCP endpoint. Both trials show that agents can implement the declared interaction in an isolated example; only the Codex example above has independent browser observations. Neither trial establishes general compliance of generated UI.
