# v0.10.0 release notes

v0.10.0 adds comparison of two candidate repairs against one recorded baseline
in Local Studio and the installed CLI.

## Changes

- Run `stylecon candidates compare baseline.json candidate-a.json candidate-b.json`.
- Select three saved runs in Studio and inspect resolved findings, regressions,
  remaining failures and incomplete checks for each candidate.
- Require matching rules, configuration, expectations and recorded coverage.
  Recommend only a unique complete improvement; ties and partial repairs do not
  earn a preference. Incomplete evidence and contradictory outcomes for identical
  source fingerprints prevent selection.
- Recompute comparisons from verified private history after restart. Historical
  comparison invalidates the live repair review and grants no write authority.
- Support known v0.9 journey report requirements and explicitly recorded expected
  values. Unknown legacy formats remain unverified.
- Upgrade affected Hono versions to 4.13.11 for GHSA-5r4p-p66f-jhc7.

## Verification and compatibility

Regression coverage includes actual rendered size and focus-restoration repairs,
CLI incomplete-evidence refusal, Studio desktop/mobile operation, persisted
history, corruption rejection and repair-authority checks. The release workflow
also verifies the exact archive through its installer and installed browser paths.

Canonical token values and supported project configurations are unchanged. `/spec`
remains the canonical rule source. Check the attached release evidence for the
tested source and remote gate results.

## Limits

Reports describe configured observations, not current source validity, complete
accessibility coverage, authenticated provenance or permission to publish. The
controlled fixtures are manually constructed and do not establish a general
model-collaboration advantage. No external model calls are required for CI.
The existing tested cache-dependency advisory exception remains documented in
SECURITY.md; no additional audit suppression is introduced.

See [candidate comparison](CANDIDATE_COMPARISON.md) for commands and decision rules.
