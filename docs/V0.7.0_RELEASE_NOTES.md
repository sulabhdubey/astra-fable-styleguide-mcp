# v0.7.0 release notes

v0.7.0 adds the local product workflows below. Use the installer, CLI archive and
checksums from the same v0.7.0 release. Attached verification evidence identifies
the tested source commit. Older archives do not contain these additions.

## Product workflow

- **Check a running React/Vite preview.** Bind configured measurements to local
  source and exact served build bytes. Observe typography, spacing, contrast and
  overflow at desktop and narrow widths. Review and apply supported literal CSS
  corrections, rebuild, recheck and undo. Both origin forms, with and without a
  trailing slash, are supported.
- **Use Local Studio.** Select a project, inspect findings, preview an exact
  correction, apply it, recheck and restore the original source. Running projects
  require a trusted rebuild after source changes.
- **Author a team constitution.** Import CSS variables as suggestions, review
  canonical rules and exceptions, then export a hash-bound constitution into a
  new destination.
- **Review PR regressions.** Compare source-bound base/head receipts and report
  new violations, resolved findings and incomplete observations separately.
- **Install a reviewed archive.** The supplied installer verifies the archive
  checksum and package identity, disables lifecycle scripts and records an
  installation receipt. Browser installation remains an explicit separate step.

## Experimental agent collaboration

Independent logical roles receive typed proposal constraints and deterministic
feedback. Exact candidate hashes bind reviews and approvals. Contradictory
requirements can stop for clarification; durable holds prevent restarting from
silently restoring approval. Candidate and approval registries remain process-local.

Caller-owned issue IDs separate concern identity from model explanations.
Distinct notes remain available, exact duplicates collapse, and pending browser
evidence remains open and unverified. Specification agreement does not complete
implementation checks or permit release with pending checks.

**No overall collaboration advantage has been demonstrated.** Protocol regression
tests and bounded live uptake checks establish narrower behaviors. See
[comparison evidence](COLLABORATION_COMPARISON.md),
[review scope](REVIEW_SCOPE.md), and [clarification](CLARIFICATION.md).

## Supported boundaries

Running-app integration initially supports trusted, same-origin loopback Vite
production previews. Repairs require explicitly mapped, byte-identical stylesheets
and supported literal declarations; arbitrary React/component rewrites are not
supported. Unsupported measurements remain explicit. This is not a complete
accessibility audit or general visual-quality evaluator.
