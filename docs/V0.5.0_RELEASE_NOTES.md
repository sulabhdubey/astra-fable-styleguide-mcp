# v0.5.0 release notes

## Product entry and setup

- Product homepage with an interactive, no-install button demo and guided MCP setup.
- The demo measures its supplied button height, shows a supplied correction, rechecks the result, and supports undo. It is not a scan of a visitor's project or evidence of autonomous model performance.
- Feedback can be copied locally; the page does not transmit or store it.
- Keyboard navigation, narrow-screen layouts, clipboard fallback, and no-JavaScript guidance are covered by browser checks.

## Standalone checking

- A locally packed CLI runs isolated Chromium for configured, trusted static projects without a desktop browser connection or external AI service.
- Supported light-DOM button/dialog and native form-error journeys produce source-bound JSON or SARIF findings and repair packets.
- Runtime failures and blocked resources remain incomplete checks, never passing results. Shadow DOM, arbitrary frameworks, custom comboboxes, and complete accessibility coverage remain outside scope.
- The CLI is not published to npm. Build and pack it from the release checkout as described in [Start Here](START_HERE.md).

## MCP and verification

- Public MCP tool annotations describe the read/compliance operations accurately.
- The release gate includes the product browser lifecycle alongside deterministic tests, generated-asset reproducibility, MCP smoke checks, dependency/source audits, and Docker build verification.
- Canonical design rules are unchanged; this release updates version metadata and the product experience.

This remains an experimental developer tool. External developer pilot results are not yet available.
