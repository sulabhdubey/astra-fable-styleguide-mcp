# v0.4.0 release notes

## Experimental local browser verification

- Configure static HTML/CSS/JavaScript projects with explicit targets and source mappings.
- Exercise button and dialog journeys, labels, error associations, declared loading/disabled states and viewport overflow through a connected browser adapter.
- Bind findings and repair packets to the exact project and canonical rule hashes.
- Inspect literal repair previews, preserve original source in private durable receipts and undo only when the current snapshot still matches.
- Use documented configuration, report, preview, apply and undo commands. See [project workflow](PROJECT_WORKFLOW.md).

## Reliability

Replacement metacharacters remain literal. Recovery covers BOM/CRLF preservation, stale evidence, interrupted locks and concurrent cooperating repairs. Multiple text references and alternative error associations are supported. Native automatic focus styles are explicitly unsupported. Provider normalization rejects malformed dimensions and replacement of existing token objects.

## Compatibility and limits

Canonical button/dialog design rules are unchanged from v0.3.0. Existing release snapshots remain immutable. The public MCP tool surface remains read-only by default. External AI is not required for CI. The local browser workflow is experimental, requires a connected browser adapter, and supports a finite set of static light-DOM interactions. It is not a full accessibility audit, arbitrary framework verifier or proof of external developer adoption. Private source receipts and reports must not be published.
